# 附录 A XSD — 来源与生成方式

本目录的 13 个 XSD 是 **GB/T 33190—2016《电子文件存储与交换格式 版式文档》
规范性附录 A** 的原文，由本技能自带的工具从标准 PDF 直接复原。

## 生成方式

```bash
python tools/extract_appendix_xsd.py "GBT 33190-2016 电子文件存储与交换格式 版式文档.pdf" \
    -o schemas --verify <参考XSD目录>
```

为什么需要"复原"而不是直接抽取 —— 该 PDF 的排版系统把 XML 标记**内部的词间空格
整个省略了**（改由字距体现），`get_text()` 拿到的是
`<xs:enumerationvalue="900"/>` 这种粘在一起的文本。

靠几何（字符 x 坐标）反推空格不可靠：`char['origin']` 含 side bearing，
`step(prev→next) = advance(prev) + lsb(next) - lsb(prev)`，实测最佳阈值 F1 仅约 62%。

工具改用**确定性规则**（XSD 语法本身即可判定边界）：

1. 属性值以 `="` 开头，**闭合**引号之后紧跟字母 => 补空格；
2. 「当前位置之后正好是某个已知属性名 + `=`」=> 补空格。

属性词表取自 W3C XML Schema 规范，**生成过程不依赖任何第三方转录版本**。

## 校验结果

| 项 | 结果 |
|---|---|
| 定位附录 A | PDF 第 96–131 页（印刷页 91–126，共 36 页） |
| 切分 | 13 个 XSD，31 条标准自带的中文注释 |
| lxml 编译为 `XMLSchema` | **13/13 通过**（含 `xs:include` 兄弟文件解析） |
| 与社区转录版 [GreenYun/OFD-Schema](https://github.com/GreenYun/OFD-Schema) 比对 | **13/13 去空白后逐字符一致** |

最后一项同时也是对转录版的独立印证：两套文本由**完全不同的路径**得到
（一份是人工转录，一份是从 PDF 确定性复原），结果一致，说明双方都没有引入失真。

## 与转录版的差异

- **多出 31 条中文注释** —— 标准附录自带，转录版未收录。例如
  `<!--资源文件定义。文档中使用的资源性文件比如图形、图像、多媒体、绘制参数(样式)等应在资源文件中统一管理。-->`
- 缩进与换行风格不同（本版本由 lxml 统一序列化，XML 声明用双引号）。

## 命名说明

`Definitions.xsd` 的文件名不能改：目录里写着 `A.6 Definition.xsd`，
但全套 Schema 的 `xs:include schemaLocation` 都指向 **`Definitions.xsd`**，
`Page.xsd` 同理。改名会导致 `include` 解析失败。
