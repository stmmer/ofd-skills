# Chapter 2: 概述（§5）

## Core Idea
OFD 文档四大特征：**文档特性**（自包含、可扩展、长期可读）、**结构**（ZIP 容器内 XML 层次）、**成像模型**（与设备无关的页面空间 + 对象空间绘制）、**扩展名**（`.ofd`）。这一章是后续所有细节的鸟瞰。

## Frameworks Introduced
- **自包含容器**：一个 OFD 文件内聚了描述、资源与签名，便于长期保存与交换。
  - When to use: 设计导出功能时，确保所有依赖（字型/图像/签名）都打包进 ZIP。
- **与设备无关的成像模型**：内容在页面/对象空间以毫米描述，输出时再换算到设备像素。
  - How: 渲染管线 = 页面空间 →（CTM）→ 对象空间 →（分辨率换算）→ 设备像素。

## Key Concepts
- **文档特性（§5.1）**：自包含、可扩展、长期可读、安全（签名/权限）。
- **结构（§5.2）**：ZIP 容器 + 多文件 XML（详见 §6/§7）。
- **成像模型（§5.3）**：坐标空间（设备/页面/对象）与绘制（详见 §8）。
- **扩展名（§5.4）**：文件扩展名 `.ofd`。
- **子集类型**：`DocType` 取 `OFD`（本标准）或 `OFDA`（OFD 存档规范）。

## Mental Models
- OFD 文件像 **一个自带字型/图像/签名的"封闭包裹"**，可独立长期保存。
- Think of the imaging model as **resolution-independent vector canvas** (mm-based).

## Anti-patterns
- **外链资源**：OFD 要求自包含，别把字型/图像放包外。
- **像素化描述**：用毫米与对象空间描述，别直接写设备像素。

## Key Takeaways
1. OFD 自包含、可扩展、长期可读、带安全机制。
2. 结构是 ZIP + 多 XML；成像模型与设备无关、以毫米计。
3. 扩展名 `.ofd`；DocType 区分 OFD / OFDA。
4. 导出时务必把所有依赖打进包内。
